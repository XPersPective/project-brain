# ADR-003 — Project Brain 3.0: Evidence-Bound State Machine, UI/Backend Quality Gates, and Quota-Aware CLI Sub-Agent Orchestration

## Status
Accepted

## Context
The user requested a comprehensive evolution of Project Brain (`2026-10-17`):
1. Projects built with the previous protocol suffered from weak/generic UI and lacked enforceable backend/state-machine rigor.
2. Tasks lacked mechanical complexity/difficulty scoring and CLI-based multi-agent delegation: high-tier models were spending quota on mechanical work instead of delegating `Tier L` and `Tier M` tasks with low/medium effort to discovered local CLI agents (`codex`, `claude`, `gemini`, `opencode`, `agy`, `qwen`, `aider`, `omniroute`, APIs) according to their subscription/quota levels.
3. A separate store-automation workflow (v4.2.0 and v2.4 backup) developed strong state transitions (`REVIEW`, `WAITING_USER`, `READBACK_FIRST`, `FIX`), digest- and contract-bound evidence (`start`, `check`, `evidence`, `review`, `accept`), `ProcessTree` verification, foreign state adoption (`legacy`), and model pool management — but coupled them with store publishing (`release-readback`, Fastlane), which the user explicitly wants kept out of Project Brain and handled by a separate publishing skill.

## Decision
Evolve Project Brain to **v3.0.0 (schema 4)** while preserving existing `.project-brain/` file formats (v0–v3 migrate to schema 4):
1. **Evidence-Bound State & Handoff (`brain.py` + `runtime_verify.py`)**:
   - Add `start`, `check`, `evidence`, `review`, `accept`, `doctor`, and `legacy` commands alongside `boot`, `map`, `init`, `new`, `changed`, `validate`, `migrate`.
   - Bind machine checks (`check`) and typed observations (`evidence`) to LF-normalized `areas_digest` and task `contract` hashes, with raw logs stored in `.project-brain/.cache/runs/`.
   - Require independent review (`Reviewer != Owner` across model aliases) for `MEDIUM`/`HIGH` risk tasks. A director prepares executable risky task specs before workers start; ready sign-off notes are protocol guidance, not authenticated runtime approval.
2. **Task Complexity & Difficulty Engine (`PB score`)**:
   - Compute a deterministic `0–100` difficulty score, recommended `Tier` (`L|M|H`), recommended `Effort` (`low|medium|high`), `Risk` floor (`LOW|MEDIUM|HIGH`), and delegation eligibility (`DELEGATABLE_CLI_L`, `DELEGATABLE_CLI_M`, `DIRECTOR_ONLY_H`, `SPLIT_RECOMMENDED`) from `Areas`, `Domains`, `Steps`, semantic risk keywords, and UI/security surface detection.
3. **System CLI Agent Discovery, Quota Tracking & Delegation (`PB agents` & `PB delegate` in `runtime_agents.py`)**:
   - Store the user-level registry at `~/.project-brain/agents.json` (auto-importing benchmark/model data from `~/.store-automation/models.json` when present, without credentials).
   - Discovery inventories installed CLIs. Live quota is supported through Codex RPC; other pools need explicit metadata. Unknown/stale readings refuse actual dispatch; L/M cannot consume the 25% director reserve. Installation, authentication, authorized billing mode and model availability are separate facts.
   - `PB delegate <PB-NNN>` builds a zero-history, bounded task prompt and executes the chosen CLI worker (`codex exec`, `opencode run`, `claude -p`, `gemini -p`, `agy --print`) inside `ProcessTree` at the lowest sufficient model & effort (`low`/`medium`), followed by automatic `PB check`.
4. **Frontend UI & Backend/State Architecture Quality System**:
   - Runtime requires executable specs, UI Triad coverage and fresh typed evidence. Reviewers evaluate Design System, responsibility/state boundaries and applicable backend recovery/concurrency/migration proof against QUALITY.md; the validator cannot judge architecture or pixels.
5. **Scope Exclusion**:
   - Exclude store publishing, Play Store / App Store uploads, and `release-readback`.

## Rationale
Synthesizing evidence-bound state management, UI/backend architectural gates, and quota-aware CLI delegation into Project Brain allows high-tier models to focus strictly on architecture, task specification, and review while low/medium-effort CLI sub-agents execute bounded tasks without exhausting subscription quotas.

## Alternatives
- Keep Project Brain 2.1 passive: rejected; lacks digest-bound acceptance, UI/backend quality enforcement, and CLI quota-aware delegation.
- Use `store-automation` directly: rejected by user because store publishing must be a separate skill, and `store-automation` 4.2 removed active CLI agent discovery and CLI task execution.

## Consequences
- `skills/project-brain/scripts/` gains `runtime_verify.py` and `runtime_agents.py`; `brain.py` and `migrate.py` remain stdlib-only and backward compatible.
- Prior directory task PB-006 remains historical blocked work; this audit does not resume publication.
- 2026-10-18 audit correction (PB-008): quality needs real observations and independent review; process containment is not an OS sandbox; identity and user waivers are declared, not authenticated. Built-in model ratings are routing estimates. Current runnable evidence supersedes the earlier unverified synthesis claims.
