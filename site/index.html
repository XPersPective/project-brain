Open-source agent skill · MIT · v3.6.1

One plan, many agents, verified handoffs.

Long projects outlive sessions: tokens run out, sessions crash, you switch models or vendors. Project Brain keeps the goal, architecture, task plan and evidence in the repository, so the next agent — strong or small, any vendor — resumes from recorded state, not chat history.

Git + Python 3.8+ · standard library only · no account, no telemetry, no server.

Session flow

  1. Session 1 · strong modelMaps the repo, interviews you, writes the target and an executable task plan.
  2. Session 2 · token limit hitExecutes tasks, commits each verified step with evidence.
  3. Session 3 · small modelSays “continue”, boots from the repo and picks up the next task.

How it works

State lives in files and commits

Never only in chat. Git owns history; commit trailers mark checkpoints and bodies carry the evidence.

The plan is the product

Tasks have exact paths, numbered steps, checkable acceptance criteria and verify commands — written so a weaker model with zero history can execute them.

Trust nothing unverified

Evidence is bound to sources, inputs, dependencies and environment. Changed inputs invalidate old proof; intact proof is reused instead of re-run.

Saves tokens deterministically

A stdlib script computes state, focus and the minimal files to load. Bounded handoffs keep the context small.

Quality gates

UI states, accessibility and responsive checks; backend boundaries, explicit transitions and idempotency. Independent review before acceptance.

Optional delegation

Route low/medium tasks to approved CLI or native workers with quota reserves — never a silent paid fallback.

Any Agent Skills tool

Manual

Download the latest release and copy skills/project-brain/ into your agent's skills directory, e.g. ~/.claude/skills/, ~/.codex/skills/, ~/.gemini/skills/ or ~/.agents/skills/.

brain.py init adds a short pointer to the project's AGENTS.md (and an existing CLAUDE.md / GEMINI.md), so every agent that opens the repository loads the skill.

Use

You sayThe agent does
“set up project brain”Maps the repo once, asks the questions that shape the target, writes target + roadmap.
“continue” / “devam et”Works the task queue until it is empty or blocked; commits each verified step.
a new request mid-wayRecords it as a P1 task and completes it plus prerequisites; unrelated backlog waits.
“where were we?”Boots read-only and reports state, focus and the next action.

Ground rules every agent follows

  • Never overwrite user work, force-push, or destructively reset.
  • Commits use your Git identity — no AI author, Co-authored-by or contributor credit.
  • Credentials stay outside the repository; Brain records only a non-sensitive reference.
  • Routing choices never authorize new scope, publishing or destructive actions.

Honest limits

Hashes establish freshness, not truth or product quality. Review records are not authenticated identity. Process containment is not a filesystem/network sandbox. Percentage quotas cannot guarantee a token budget. Reliable results still depend on the agent following the protocol. App-store publishing is out of scope.

Privacy: the skill runs locally, reads only the current repository and never reads or stores credential values. See PRIVACY.md.
