# ADR-004 — Durable opt-in orchestration

Status: Accepted for implementation, 2026-10-31.

The user authorized the orchestration roadmap and specified SOLO/SERIAL for this
initial development session. On 2026-11-01 the user authorized an independent
read-only auditor and production validation. Read-only Codex host probes validate
launch/collection/interruption; no paid-provider fallback is used.

Keep Brain tasks and existing evidence commands authoritative. Add opt-in local
SQLite run accounting outside the repository, shared by linked Git worktrees.
Prepare immutable requests before external effects; reconcile uncertain effects
instead of retrying blindly. Separate process, verification and integration states.
Pool remains a separate product responsible for authentication, quota and process
execution; consume its existing submit/get/cancel RPCs without a new dependency.
Native execution is an explicit host bridge, never a Python claim to launch host tools.

Implement incrementally through the existing roadmap. Preserve legacy delegate
journals and commands. Do not claim native live-provider support or measured token
savings from synthetic tests. Do not recreate the retired source Brain tracker.
Use scoped context packets and bounded event views; preserve complete reports
privately. One integration writer and isolated delegated execution workspaces.

The source roadmap is the development ledger; update it as runnable evidence is
obtained. New module boundaries are context, runs/scheduling, and host/Pool control;
reuse existing security, task, evidence and Git helpers rather than duplicate them.

Production hardening: origin session policy is authoritative across candidates;
immutable receipt identities/strengths bind ownership; candidate intent/contracts
cannot weaken the origin. Both commit and target hooks are observed before PASS.
Restore relocates observations, never control of imported running jobs. Default
protocol-1 regressions exercise independent review and acceptance, not just legacy mode.

Automatic startup upgrade, 2026-11-01: the user requests supported old project
state to upgrade on use without a separate migration decision. Reuse the existing
raw-backup/config-last converters before orientation reads focus and before boot
resets session choices. Include no-Git and unborn-Git projects; never initialize
Git or a missing Brain. Read-only startup and merge/rebase remain observational.
Reject future versions and unrecognized legacy shapes before mutation. Keep
installed-skill distribution separate from per-project state conversion.
