# ADR-001 — Evidence-based state recovery

## Status
Accepted

## Context
The prior design (docs/design/04-critique.md) intentionally used the latest PB mention
as a global baseline to avoid false positives from inconsistent domain names.
The recovery regression now demonstrates that a rule-only PB commit conceals two
external source changes, and an auth checkpoint must not reconcile billing.
Task absence also cannot prove that a WIP or abandoned task completed.

## Decision
Use explicit non-WIP per-domain Current checkpoints (including all). Keep the last
Current edit as a legacy fallback. Recognize Git completion only with verification
and task absence in that commit. Retain DONE plus Evidence when Git is unavailable
or a completion commit is pending. Missing evidence never satisfies a dependency.

## Rationale
False positive drift can be reviewed; silently lost drift or false completion can
make a successor implement work against a false architecture or unmet dependency.

## Alternatives
- Latest PB mention: cheaper, but the regression proves information loss.
- New state database: duplicates Git and adds an unnecessary dependency.

## Consequences
- Domain names must match Sources headings; mismatches remain visible as drift.
- History scans have extra read-only Git queries; no new persistent cache.
- Scope stays the current audit: PB-001 implementation, PB-002 migration continuity,
  PB-003 documentation. Existing target and user Goal remain unchanged.
