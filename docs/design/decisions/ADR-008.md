# ADR-008: Acyclic Core Runtime, CAP-Only External CLI Separation, Streamlined Setup and Advisory Qualification (4.0.0)

Status: Accepted

## Context

By release 3.12.0, Project Brain had accumulated:
1. Two overlapping external-CLI execution stacks (`runtime_agent_pool.py` talking
   to the separate `cli-agent-pool` repository, plus ~2,300 lines of legacy
   `--backend direct`, OmniRoute adapters, standalone CLI discovery and session
   accounting in `runtime_agents.py`, `runtime_pool.py`, `runtime_discovery.py`).
2. A 20-module runtime graph containing 118 lazy function-body imports and
   strongly connected import cycles (`brain ↔ runtime_*`, `runtime_executor_policy
   ↔ runtime_relay ↔ runtime_setup`).
3. High startup ceremony: a mandatory 7-item Turkish setup questionnaire, a
   CDN-backed `setup-form.html`, `setup clarify`, and a 5-minute blocking wait
   pattern that conflated core Git-native memory with opt-in power features.
4. A mandatory `MODEL_QUALIFICATION_REQUIRED` gate that deadlocked fresh
   repositories on CAP catalog/category models, alongside an unused `"speed"`
   (`balanced`/`turbo`) policy field that altered no runtime dispatch behavior.

## Decision

1. **Clean Product Separation (CAP-Only External CLIs):** Remove legacy
   `--backend direct`, OmniRoute, standalone CLI discovery and direct-session
   accounting (`runtime_agents.py`, `runtime_pool.py`, `runtime_discovery.py`,
   `AGENTS_CLI.md`). Core Project Brain runs standalone with `solo` and host
   `native` agents (zero external dependencies). External CLI lifecycle belongs
   exclusively to the separate `cli-agent-pool` (CAP) companion.
2. **Acyclic Layered Runtime:** Extract a zero-internal-import foundation
   (`runtime_core.py`, `runtime_scoring.py`, `runtime_actors.py`), eliminate all
   lazy internal imports and import cycles, and centralize crash-safe atomic
   writes (`fsync` + `os.replace` with Windows retry), OS file locks, Python
   3.8–3.13 UTC ISO parsing, and secret-scrubbed Git subprocess execution.
3. **Sharp Core vs Power Setup:** Replace the 7-item Turkish form + CDN HTML +
   `clarify` ceremony with safe core defaults (`native · parallel (auto) · QRP
   off · BRP off`), a language-neutral single-line `setup ask` summary, instant
   `setup confirm`, inline `PB policy --source ... --confirm` flags, and opt-in
   `--advanced` disclosure for power features (`mixed`/`cap-*`, `QRP`, `BRP`,
   durable SQLite `runs`). Keep `SKILL.md` under 4.5 KiB.
4. **Advisory `PB qualify`:** Unqualified opaque CAP models emit an advisory
   `qualification_warning` (or infer standard CAP tier categories) instead of
   deadlocking fresh repos; explicit `PB qualify` overrides remain strictly
   enforced once recorded. Hard safety gates (ESP allowlists/pins/categories/
   effort/paid-API, reviewer independence, evidence/acceptance) remain unchanged.
5. **Remove Unused `speed` Field:** Drop `speed` from active schema, setup and
   docs while harmlessly tolerating legacy `"speed"` keys when loading v3.11/v3.12
   `executor-policy.json` files.

## Consequences

- Runtime stays strictly acyclic across 20 focused modules (~12.7k LOC) with
  zero circular imports, zero lazy internal imports, and 100% Python 3.8 grammar
  compliance (retiring ~2,300 LOC of legacy direct-CLI code while extracting
  `runtime_core.py`, `runtime_scoring.py`, and `runtime_actors.py`).
- `SKILL.md` shrinks from 6,358 B to 4,160 B (-34.6%, well below the 4,500 B
  release budget), reducing mandatory boot prompt footprint while keeping all
  authority and verification gates intact.
- Existing v3.x consumer projects upgrade automatically on `orient`/`boot` with
  raw backups; legacy `--backend direct` invocations fail cleanly with exit 2
  directing callers to CAP (`runs`/`delegate`).
